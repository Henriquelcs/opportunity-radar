# Exemplo End-to-End

Este documento é um contrato de preenchimento. Não inventa um caso real.

1. Dor encontrada: aguardando oportunidade real selecionada.
2. Fonte original: URL preservada pelo Runner V2.
3. Conteúdo original: imutável.
4. Tradução: camada separada.
5. Sinais: categorias detectadas.
6. Score: score de descoberta explicado.
7. Possível falso positivo: decisão de curadoria.
8. Curadoria: classificação e motivo.
9. Comprador: hipótese até contato.
10. Personal fit: inferência explicada.
11. Facilidade de validação: depende do menor teste e canal.
12. Custo: não informado até premissa humana.
13. Monetização: hipótese.
14. Menor teste: registrado no workspace.
15. Plano: ações e critérios.
16. Resultado: evento real.
17. Continuar ou descartar: decisão humana.
18. Plano de MVP: somente após aprovação.
19. Primeira receita: somente pagamento registrado.

O primeiro exemplo completo deve ser preenchido com uma oportunidade real após a validação.
